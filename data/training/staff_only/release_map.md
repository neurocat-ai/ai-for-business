## S3. RAG

Дополнительно открыть:
- `03_knowledge_base/*`

Обязательно использовать сценарии:
- с прямым ответом в базе;
- с ответом, который требует сопоставления нескольких документов;
- без подтвержденного ответа в базе, чтобы проверить отказ от выдумывания.

## S4. Agent

Дополнительно открыть:
- доступ к `create_demo_request`;
- рабочее внешнее состояние на основе `leads.csv` и `demo_requests_seed.csv`;
- описание business tool в объеме учебной инструкции.

Agent должен показать минимум три поведения:
1. action - данных достаточно и действие допустимо;
2. ask - данных недостаточно;
3. handoff/no action - действие неуместно или рискованно.

Отдельно проверить ответы tool `already_exists` и `lead_not_found`.

Перед каждым независимым тестовым сценарием возвращать состояние заявок к `demo_requests_seed.csv`, чтобы результат одного запуска не влиял на следующий.

## S5. Сквозное тестирование

Открыть:
- `02_cases/holdout_cases.csv`

Holdout не используется для настройки решения до финального теста.

Студент выбирает один целевой сценарий и тестирует одну обоснованную конфигурацию: RAG, Agent или RAG + Agent.

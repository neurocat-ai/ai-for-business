# Tool contract: create_demo_request

## Назначение

`create_demo_request` представляет внешнее бизнес-действие: зарегистрировать заявку на проведение демо.

Техническая реализация может использовать Google Sheet + подготовленный endpoint / Apps Script. Для студента это business tool, а не упражнение по работе с таблицами.

## Сигнатура

```text
create_demo_request(
  lead_id,
  company,
  contact,
  use_case,
  preferred_time,
  comment
)
```

## Аргументы

Обязательные:
- `lead_id` - ID лида во внешнем состоянии;
- `company` - компания;
- `contact` - контакт для связи;
- `use_case` - конкретный сценарий, который клиент хочет обсудить.

Опциональные:
- `preferred_time` - пожелание по времени;
- `comment` - дополнительный контекст для менеджера.

## Возможные ответы

### created

```json
{
  "status": "created",
  "request_id": "DEMO-2041"
}
```

### lead_not_found

```json
{
  "status": "lead_not_found"
}
```

### already_exists

Для лида уже есть активная заявка на демо.

```json
{
  "status": "already_exists",
  "request_id": "DEMO-2004"
}
```

### missing_required_field

```json
{
  "status": "missing_required_field",
  "field": "contact"
}
```

### tool_error

```json
{
  "status": "tool_error"
}
```

## Проверки инструмента

Tool:
1. проверяет обязательные поля;
2. проверяет существование `lead_id`;
3. проверяет активную заявку на демо;
4. при успешной проверке создает запись;
5. присваивает `request_id`;
6. возвращает результат.

## Что tool не решает

Tool не определяет:
- соответствует ли запрос возможностям продукта;
- достаточно ли лид квалифицирован;
- нужен ли старший менеджер;
- допустимо ли обещать скидку или нестандартную интеграцию;
- надо ли вообще создавать демо.

Это решение принимает Agent на основании входа, базы знаний и правил квалификации.

## Human confirmation

В базовом учебном сценарии перед созданием заявки используется подтверждение человека.

## Дубликаты

Agent может не знать заранее, что заявка уже существует. Если пользователь явно просит зарегистрировать демо и других оснований для остановки нет, Agent может вызвать tool после подтверждения.

Если tool возвращает `already_exists`, Agent:
1. не утверждает, что создал новую заявку;
2. сообщает о существующей заявке;
3. при необходимости передает повторный запрос менеджеру.

## Reset

После учебной попытки состояние заявок возвращается к `demo_requests_seed.csv`.
